# PKForge bank model

Status: proposed Phase A contract, 2026-07-17. This schema is intentionally engine-neutral and preserves original entity bytes.

## Storage format

The bank is a versioned directory/archive-backed store:

```text
bank/
  manifest.json             # schema version, bank ID, timestamps, counts, integrity metadata
  entities/<entity-id>.bin # exact imported raw entity bytes, immutable by default
  boxes/<box-id>.json       # user layout, names, wallpaper, ordered entity IDs
  tags.json                 # tag definitions and colors
  provenance/<entity-id>.json
  backups/<timestamp>-<revision>/...
```

The whole directory exports/imports as one ZIP archive with a manifest and per-file SHA-256 hashes. Import stages into a temporary directory, verifies every hash and schema version, then swaps the bank root atomically. No cloud dependency.

## Manifest schema (v1)

```json
{
  "schemaVersion": 1,
  "bankId": "stable-guid",
  "createdUtc": "2026-01-01T00:00:00Z",
  "updatedUtc": "2026-01-01T00:00:00Z",
  "nextBoxOrder": 0,
  "entityCount": 0,
  "boxCount": 0,
  "archiveHash": "sha256-or-null"
}
```

## Entity record

`entities/<id>.bin` is the exact raw stored entity bytes as imported or last explicitly converted. It is never replaced by a lossy normalized representation.

```json
{
  "entityId": "stable-guid",
  "rawFile": "entities/<id>.bin",
  "format": "PK7",
  "generation": 7,
  "byteLength": 232,
  "sha256": "...",
  "createdUtc": "...",
  "updatedUtc": "...",
  "display": {
    "species": 25,
    "form": 0,
    "nickname": "Pikachu",
    "isShiny": false,
    "level": 50
  },
  "tags": ["competitive"],
  "notes": "",
  "source": {
    "kind": "save|file|qr|bank-import|generated",
    "saveUriFingerprint": "optional-non-secret-id",
    "saveGame": "optional version",
    "slot": { "box": 0, "slot": 0 },
    "addedUtc": "...",
    "originalFormat": "PK7",
    "originalGeneration": 7
  }
}
```

Display fields are a cache for search/rendering, not authority. On load or transfer, the engine reparses `rawFile`; corrupt/mismatched cache data is rebuilt. IDs are generated by PKForge and are not derived from PID/EC or trainer identity.

## Boxes and ordering

```json
{
  "boxId": "stable-guid",
  "name": "Living Dex 01",
  "order": 0,
  "wallpaper": "fallback-default",
  "slots": ["entity-id-or-null"],
  "tags": ["living-dex"]
}
```

Boxes are unlimited. `slots` is sparse/nullable and has no fixed generation capacity; UI chooses a page size. An entity may appear in multiple boxes only through explicit references; deletion is reference-safe and requires confirmation. Search indexes entity metadata and reparsed engine fields.

## Transfer contract

A bank-to-save transfer never writes raw bytes directly:

1. Parse the canonical raw entity with the source format.
2. Select the destination save's format/version and call the engine's explicit conversion path.
3. Re-run destination legality and expose warnings/report.
4. Stage the converted entity in an isolated save clone.
5. Require user commit; execute backup → validate → atomic write.
6. Preserve the original bank entity and append transfer provenance.

Failed conversion or legality does not mutate either bank or save. A generated destination entity is a new immutable bank record only when the user explicitly chooses “add converted copy.”

## QR transfer (PKF1)

Mons travel between installs as a QR code carrying the raw entity file itself
(PKSM-style), not a text rendering of it. `QrEntityCodec` (PKForge.Domain, pure)
defines the envelope; the QR layer lives in the app (`QrEntityService`, `QrPopup`).

```text
offset 0      4 bytes   magic "PKF1"
offset 4      1 byte    envelope version (currently 1)
offset 5      1 byte    entity generation (1-9)
offset 6      2 bytes   entity length N        (little-endian)
offset 8      N bytes   raw .pk file bytes, exactly as ExportSlot writes them
offset 8+N    1 byte    species-name length M  (UTF-8 bytes)
offset 9+N    M bytes   species name, UTF-8 - human confirmation before import
```

- The parser is strict: wrong magic/version, out-of-range generation, length that
  does not consume the payload exactly, or invalid UTF-8 name is rejected. Import
  still requires the engine to recognize the bytes (`TryDescribeEntity`).
- QR encoding is byte mode over ISO-8859-1 (one code point per byte, the mapping
  ZXing-based scanners reverse exactly) at error-correction level M. The largest
  entity (Legends: Arceus, 344 bytes) plus envelope fits one code comfortably; no
  chunked multi-QR split exists or is needed.
- Scanning picks a screenshot/photo, decodes the QR, previews species/level/OT,
  and only a confirmed receive reaches the bank (source kind `qr`).

## Versioning and migrations

- Every persisted JSON document carries `schemaVersion`.
- Readers reject future versions without modifying files.
- Migrations are pure functions `vN -> vN+1`, applied in memory, validated, then committed to a new backup revision.
- The first release supports migration from v1 onward; no silent field dropping is allowed.
- Archive import validates paths (no absolute paths or traversal), duplicate IDs, byte lengths, SHA-256, and referenced entities before swap.
- Bank backup retention follows the save backup policy and is independently restorable.

## Decisions and open gates

Chosen: raw bytes plus metadata, GUID IDs, JSON sidecars, archive export, immutable imports, explicit conversion on transfer. This avoids irreversible normalization and supports future generations.

Before implementing persistence, confirm this schema and migration policy because changing entity identity, byte retention, or archive semantics later is costly. Network sharing, moderation, and server retention remain out of scope.
